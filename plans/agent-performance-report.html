What I'd change first

  1. Never let a tap-out expire unseen. Route undecided tap-outs to main after a short timeout, so main decides or escalates instead of letting the work lapse. That's 29 lost decisions in 48h.
  2. Get product and QA questions answered faster. Main answers coders in minutes; product's and QA's questions sit for hours waiting on a person. Have main try those first, and escalate only true product calls.
  3. Raise QA first-pass. Have the coder run the QA brief's checks before certifying, and make sure the copy's app is restarted onto the committed code before QA starts. Twice tonight QA tested stale code.
  4. Fewer harness restarts per promote. Every promote currently restarts or reloads the harness and re-sends resume offers to every agent.
  5. Record token usage per turn so Codex and Claude can be compared on cost. That's part of story 1092.

Limits of this report

  • System notices and operator nudges are counted together; the data has no field telling them apart.
  • Story cycle time by stage isn't here: task open and close times live in the harness, not in this database, so they need their own query.
  • Token usage isn't recorded, so cost is missing entirely.
  • 90 framework issues were filed in the window, but operator sessions file them too, so that count isn't agent-only.
